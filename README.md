# ЛР №3. ООП: реализация абстрактных структур данных (C++ и Go)

Структуры: динамический массив, односвязный и двусвязный списки, стек, очередь,
**Complete Binary Tree** (вариант из ЛР1) и хеш-таблица (метод свёртки, линейное
пробирование и двойное хеширование - из ЛР2). Обе реализации имеют одинаковые команды,
одинаковый вывод и **побайтно одинаковые файлы сериализации** (файл, сохранённый в C++,
читается в Go и наоборот).

```
cpp/   C++20, CMake: include/ds (интерфейсы), src, app, tests (Boost.Test, GoogleTest, Catch2), bench
go/    Go 1.22: ds (структуры), cli (команды), cmd/lab3, тесты testify, бенчмарки testing.B
```

## C++ (cpp/)
Зависимости (Ubuntu): `cmake ninja-build g++ libboost-test-dev libgtest-dev catch2 libbenchmark-dev gcovr clang-tidy cppcheck`

| Что | Команда |
|---|---|
| сборка и тесты | `cmake -S . -B build -G Ninja && cmake --build build && ctest --test-dir build` |
| покрытие (HTML) | `scripts/coverage.sh` -> `build-cov/coverage/index.html` (порог 85%) |
| бенчмарки | `scripts/bench.sh` (Google Benchmark, результаты в `bench_result.json`) |
| линтеры | `scripts/lint.sh` (cppcheck + clang-tidy, конфиг `.clang-tidy`) |
| приложение | `build/lab3_app [--file data.file] [--query "MCREATE a"]` |

Тесты разнесены по фреймворкам: **Boost.Test** - массив и списки, **GoogleTest** - стек, очередь,
дерево, **Catch2** - хеш-таблица, сериализация, интерпретатор команд. Покрытие считается по сумме всех трёх.

## Go (go/)
Один раз: `go mod tidy` (скачает testify и создаст go.sum).

| Что | Команда |
|---|---|
| тесты | `make test` |
| покрытие (HTML) | `make cover` -> `coverage.html` (порог 85%) |
| бенчмарки | `make bench` |
| линтеры | `make lint` (gofmt, go vet, golangci-lint, конфиг `.golangci.yml`) |
| приложение | `go run ./cmd/lab3 [--file data.file] [--query "MCREATE a"]` |

## Команды (одинаковы в C++ и Go; полный список - `HELP`)
Массив `M*`, односвязный список `F*`, двусвязный `L*`, стек `S*`, очередь `Q*`,
дерево `T*`, хеш-таблица `H*`, общие `PRINT SIZE LIST DROP CLEAR`,
сериализация `SAVE <имя> BIN|TXT <путь>` и `LOAD <имя> BIN|TXT <путь>` (тип определяется по заголовку).
Команды, изменяющие данные, дописываются в файл данных и воспроизводятся при запуске (как в ЛР1/ЛР2).

## Форматы сериализации
Бинарный (little-endian): `"DSB1"`, тип (u8), далее данные структуры.
Строки: `u32 длина + байты`; списки/стек/очередь/массив: `u32 количество + элементы`;
дерево: обход по уровням с пропусками (`u8 флаг [+ i32]`); хеш-таблица: режим, ёмкость и все ячейки (состояние + ключ).
Текстовый: `DSTXT 1`, `TYPE <тип>`, затем `COUNT n` и по строке на элемент (`\\`, `\n`, `\r` экранируются).

## Что показывает ООП-часть (для защиты)
- интерфейс `IStructure` (абстрактный класс, виртуальный деструктор, vtable) и 7 наследников;
- идиома NVI: `saveBinary/loadBinary` проверяют заголовок, содержимое - в приватных виртуальных `do*`;
- правило пяти (копирование, перемещение, copy-and-swap), конструкторы/деструкторы, `const`-методы;
- фабрика `makeStructure` возвращает `std::unique_ptr<IStructure>` (полиморфизм);
- загрузка атомарна: при ошибке формата структура остаётся без изменений.
